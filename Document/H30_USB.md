# H30 USB 接入与单次姿态查询

ESP32-S3 原生 USB 口（GPIO19=D-、GPIO20=D+）连接 H30 Type-C，下载口的 USB-UART 桥继续连接电脑。保持已验证的 5V VBUS 供电和数据线连接；H30 通过 USB 供电时不要并接未隔离的第二套 5V。该功能不占用现有 UART1、UART2 和扫码软串口。

固件使用 Arduino Core 自带 USB Host，识别 CH9102F `1A86:55D4`，从配置描述符发现 CDC 接口及 Bulk IN 端点，标准 CDC 请求设置 460800、8N1、DTR/RTS。现有 PlatformIO 板卡、分区、依赖和 OTA 设置保持原值，仅切换原生 USB 为 Host 模式；日志及上位机仍走 UART0。

## 上位机操作

编译并下载固件后，运行 `python upper_computer.py`，连接 ESP32 下载口对应串口，完成协议握手，点击连接栏的“查询陀螺仪姿态（单次）”。每次点击发送一条命令，只更新一次 Pitch、Roll、Yaw 和样本年龄，不开启定时查询。

手动发送（末尾加换行）：

```text
{CMD,IMU,GET}
```

成功示例：

```text
{RSP,IMU,GET,OK,0.234204,-0.108825,-68.936127,5}
```

字段依次为 Pitch、Roll、Yaw（度）和样本年龄（毫秒）。`IMU GET` 始终返回 H30 设备原始角度；地图参考航向通过下节的独立命令查询。不写入小车 POSE，也不用于运动闭环。显示内容是本次快照，不代表之后仍在线。

## 地图航向标定

模块安装为车体 X=-模块 X、Y=模块 Y（车头方向，与仓库 Y 正向移动一致）、Z=-模块 Z。当前只建立平面 Yaw 参考，不输出经过安装变换的完整车体欧拉角；不能按轴符号逐项取反欧拉角。

Debug 选择启停区、Release 开局设置初始位姿，以及上位机 `POSE SET` 显式校准位姿时，用同一时刻的新鲜 H30 样本建立参考：

```text
地图航向 = wrap360(标定地图航向 + 当前原始Yaw - 标定时原始Yaw)
```

例如实车朝向已确认为 180°，此时 H30 Yaw=-68°，之后原始 Yaw 变为 22°，地图航向就是 270°。跨越 ±180° 时按同一公式环绕。倒装不直接将 Yaw 取负；这里采用标准 Yaw 与地图左转同为递增的约定，启用电机航向闭环前必须实车确认正负。标定只建立偏移，无法验证转向正负或修正磁干扰。

这些入口必须代表车体当前实际朝向：车尚未摆到指定朝向时，不应仅为预览而校准。普通节点到达和运动结束的理想航向推算不重新标定 H30。雷达扫描准备动作目前也不提供实际定位结果，不在其完成时自动标定。以后新增外部定位校准点时，在该位置确认实际航向后调用 `CalibrateH30MapHeading(heading)`。

成功事件为 `{EVT,IMU,REFERENCE,OK,heading}`；失败事件为 `{EVT,IMU,REFERENCE,ERR,原因}`。参考同步失败不改变原 `POSE SET` / 选区的语义：理想位姿仍设置成功，但 H30 无有效参考，不能据 ACK 判断其已完成融合。失败不会排队等待将来的样本；数据恢复后需重新执行实际位姿标定。

上位机点击“查询地图航向（单次）”，发送 `{CMD,IMU,HEADING}`，回复例如 `{RSP,IMU,HEADING,OK,270.000,5}`。未标定返回 `NOT_CALIBRATED`，其他离线/过期错误同下表。USB 断开或接收故障清除参考；姿态样本中断超过 200 ms 后恢复也清除参考，必须重新标定。

地图参考与原 `currentPose.theta` 理想航向分别保存，原比赛节点导航仍使用原逻辑。新增的 [连续过弯独立试跑](continuous_trial.md) 会主动使用该地图航向闭环控制电机；试跑结束后保存估算位置和最后实测航向。位置 X/Y 仍来自既有定位或开环推算，不能由这项航向标定推导出真实位置。

错误回复为 `{RSP,IMU,GET,ERR,原因}`：

| 原因 | 含义 |
|---|---|
| INIT | USB Host 或任务初始化失败 |
| OFFLINE | 未连接目标设备、正在配置或正在恢复 |
| NO_DATA | USB 已接通，但尚未收到含合法姿态的帧 |
| STALE | 最近姿态超过 200 ms，禁止返回旧角度 |
| FORMAT | 查询带了多余参数 |

查询与现有串口命令共用任务。正在执行阻塞动作时，回复可能延后；上位机等待 3 秒后显示超时，可在动作结束后重新查询。

## 接收与恢复

H30原协议还支持三轴加速度0x10和角速度0x20；当前接收器仅发布姿态0x40。加速度包含重力，静止和匀速不可凭加速度区分，不用于确认直线目标到位。独立试跑用连续新姿态计算转速、确认航向稳定，直线位置仍为命令积分估算，详见[混合路径试跑](continuous_trial.md)。

独立 Host/Client 任务处理总线与数据，客户端回调最多解析 512 字节，不调用业务动作、等待函数或逐帧打印。YIS 按 LEN 分帧、双字节累加校验、检查全部数据项边界，只发布含 `0x40 / 12` 姿态项的完整帧。多任务查询通过短临界区获取完整快照。

断开或传输错误立即使缓存无效；先停止接收，halt/flush Bulk IN，等待在途传输回调后释放接口和设备，每秒检查枚举地址并重试。不会重启整机。控制传输超过 3 秒时标记离线；EP0 仍在途时保留资源，等待完成或物理拔出后再回收，避免释放仍被 USB 栈使用的对象；这种情况下可能需要拔插 H30 才能恢复。

## 验证

`pio run` 编译业务固件。`python -m unittest discover -s tests -p 'test_imu_query.py'` 验证单次请求、回复解析、超时和离线显示；`test_h30_protocol.py` 使用 ESP32-S3 编译器执行编译期断言，覆盖负角度、校验错误恢复、分片、多帧、字段越界、最大帧、半帧复位。

此集成仍需实车验收：分别转动三个轴确认角度/符号，运行原有业务检查查询，拔出后查询应报 OFFLINE，重插后应恢复；暂停 H30 输出时应报 STALE。未完成这些实机步骤前，不能将编译和无硬件测试视为热插拔或精度验收。
