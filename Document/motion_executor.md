# 统一运动执行与计时

实现日期：2026-10-21。软件迁移及本地回归已完成；未烧录、未实车验收，不能据此宣称达到 180 秒。

## 执行模型

`Task_MainStateMachine` 每 10 ms 调用一次 `CompetitionFlow::tick()`。业务阶段只提交一次作业并轮询同一编号，收到 DONE 才推进；圆盘物料登记和进度由真实动作末端提交。ACK、目标位姿和下发成功不能代替完成。

### 主状态机从哪里读

直接阅读 `src/competition_flow.h` 中标有“主状态机”的 `tick()`：所有正常业务阶段集中在一个 `switch(phase)` 中，按执行顺序排列，不再使用数字 `step` 或跳转到不同业务函数寻找步骤。

| 阶段名 | 业务顺序 |
| --- | --- |
| `START_*`、`SCAN_TASK` | 收臂 → 确认起始区 → 准备扫码姿态 → 等待启动 → 扫码 |
| `DISC_*` | 导航并提前 LOOK2 → 对齐 → LOOK3 → 取三件（前两件抓完重新 LOOK3） |
| `COARSE_NAVIGATE/ALIGN/PLACE` | 导航并提前 LOOK → 对齐 → 放三件 |
| `COARSE_WAIT_RETRIEVE/RETRIEVE` | 保留原间隔 → 在粗加工区取回三件 |
| `TEMP_*` | 导航并提前 LOOK → 对齐 → 第一轮放料 / 第二轮叠放 |
| `HOME_*` | 路径前收臂 → 导航并提前 LOOK4 → 观察准备 → 角点对齐 → 归位 |

第一轮暂存放料完成后回到第二轮圆盘取料，第二轮叠放完成后返家。`secondRound` 只选择本轮任务、视觉模式和层高。对外 `RobotState` 编号及 PHASE 日志名称、边界保持原样；因此粗加工区取回仍计入 `PLACE_TEMP1` / `STACK_TEMP2` 大状态，内部已单独命名。每次 tick 仍只处理一个阶段，保留原动作提交、轮询与等待时机。

`MotionExecutor` 是唯一运动工作任务，交替推进底盘 Runner、机械臂 Sequence 和视觉闭环。串口、视觉输入只解析、提交及发布反馈。启动时的硬件初始化和原有紧急超时停车保留。试跑也通过该执行器，不能与正式路线争用电机。

| 接口/类型 | 含义 |
| --- | --- |
| `SubmitMotion(request)` | 按值复制请求，返回作业编号；0 表示未提交 |
| `SubmitMotion(request, false)` / `LaunchMotion(id)` | 串口先保留作业，再发既有 ACK，最后放行执行，避免完成事件抢在 ACK 前 |
| `GetMotionStatus(id)` | 查询 QUEUED、RUNNING、DONE、FAILED、CANCELLED，附阶段、原因、时间及路径/机械臂联合进度 |
| `CancelMotion()` | 取消代次并唤醒工作任务停车，沿用现有业务失败状态；保留夹爪位置 |
| `MotionExecutorSetOta(active)` | OTA 前取消并禁止新作业；退出 OTA 后旧作业不续跑 |
| `WaitMotion(id)` | 旧接口的同步兼容层；正式主流程与串口分发不使用 |

队列同时容纳一个待执行作业，最近八个终态可查询。调用方需保留有效作业编号并及时消费结果。Release 雷达姿态成功缓存独立保存，重复请求不会累加相对位移。

底盘有限动作保留既有换算、轨迹、四轮到位及同步触发语义；扫码通过有限状态机轮询二维码和手动码。机械臂 Program 保留原动作顺序、坐标、速度、正反向各九组延时与多圈线缆路径规划。总线递归锁覆盖完整请求/回包事务，不覆盖机构运动等待；逐次查询仍可能等待原有硬件通信超时。

## 完成策略与参数

新增参数位于 JSON 的“运动执行”分组，运行时追加注册，既有参数编号顺序不变。两个距离提前量参数仅兼容保留，不再影响触发；其余三项默认值为 0。

| 参数 | 作用 |
| --- | --- |
| `look末段提前量(mm)` | 兼容旧参数；不再参与展开时机判断 |
| `look2末段提前量(mm)` | 兼容旧参数；不再参与展开时机判断 |
| `机械臂反馈完成` | 0 保留原等待；1 显式使用实际电机/舵机反馈，无自动降级 |
| `反馈后夹持保持(ms)` | 反馈模式夹紧实际到位后的工艺保持 |
| `反馈后释放保持(ms)` | 反馈模式松爪实际到位后的工艺保持 |

路径状态暴露最后平移段、剩余距离、末端转向。视觉前 look/look2/look4 在最终连续平移段之前的转向阶段开始时触发一次；单段直行从起步准备，短末段也不等到停车。提前展开仅作用于导航作业附带的观察姿态；手动姿态、路径前初始化和其他独立机械臂作业维持原顺序。返航将 look4 并入导航，之后保留原航向修正，不重复展开。即使 look 已提前完成，也必须底盘完成且机械臂准备完成才能开启视觉。末端存在转向时，提前展开期间是否干涉需先在对应路线验证。两轮圆盘均先 look2 和 DISC 对齐，结束后再 look3，实测转台 90°±5°后开启物料识别；抓完前两件也需重新 look3 并清理旧识别缓存。

look/look2/look3/look4 的首段抬升等待直接按 `abs(170-currentArm.high)*1500/170` 毫秒估算，使用记录的指令高度；高度差 0/85/170 mm 分别等待 0/750/1500 ms。look 重复指定相同高度的就绪步骤不再额外等待 1000 ms；其他动作及路径前初始化延时不变。

反馈模式对 5/6 号电机读取到位标志及实际位置，对转台/夹爪读取实测角度；`currentArm` 仍是命令目标。协议依据仓库 [EMM V5.0 说明书](张大头EMM%20V5.0驱动说明书.pdf) PDF 第 47–49 页核对：位置一圈 65536 单位、到位标志掩码 0x02。实机驱动细分、方向、回零、换算和响应仍待核验。

上位机动作组页在反馈模式下将不参与执行的运动延时置灰并禁用编辑；显式稳定等待仍有效，正反向单组的“放料平移”仍是保留的等待。公共组与单组使用场景不同，不能将所有延时统一删去。夹持/释放使用上述独立保持参数。旧延时仍可保存，切回计时模式后生效。

## 计时日志

时间为设备开机毫秒，编号 0 为业务/视觉，其他编号为运动作业。

```text
{EVT,MOTION,RUN_START,0,1000}
{EVT,MOTION,PHASE,0,1010,READ_TASK}
{EVT,MOTION,SPAN,7,2000,NAVIGATION,BEGIN}
{EVT,MOTION,STEP,7,2100,0,LOOK_LIFT,BEGIN}
{EVT,MOTION,STEP,7,3600,0,LOOK_LIFT,END}
{EVT,MOTION,FLAG,7,3900,CHASSIS_DONE,1}
{EVT,MOTION,SPAN,7,3900,NAVIGATION,END}
{EVT,MOTION,RESULT,7,4000,DONE,2000}
{EVT,MOTION,RUN_RESULT,0,181000,DONE,180000}
```

以上仅为格式示例，不是实车记录。完整日志还包含 ARM_PROGRAM、视觉首帧/会话、底盘分段及步骤区间。未收到首帧便关闭会话记录 ERROR，保留首帧区间未完成，不补造首帧耗时。取消/错误步骤同样不会补造结束事件。

```powershell
python scripts/summarize_motion_log.py run.log > timing.md
```

脚本兼容带 RX 前缀的上位机日志，输出正式比赛边界、阶段耗时、作业与分项累计/区间并集、未结束项。嵌套和并行分项不可跨行相加，重叠量不能当作相对旧流程的提速收益。每个文件只放同次开机的一场比赛，要求 millis 未回绕；缺失起止时不推断总成绩。
